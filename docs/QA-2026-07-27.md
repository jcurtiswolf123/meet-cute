### The two "known dev-only flakes" were environmental, and are gone

`test:journey:application` and `test:launch:roles:e2e` were previously recorded
as intermittently timing out. Both pass reliably when pointed at a production
build instead of the Turbopack dev server:

```bash
npm run build && npm start &
MEMBER_E2E_BASE_URL=http://127.0.0.1:3009 npm run test:journey:application
ROLE_E2E_BASE_URL=http://127.0.0.1:3009 npm run test:launch:roles:e2e
```

Run them that way. They were never application bugs.

## Defects found and fixed

### ISSUE-001 (high): pages rendered blank without JavaScript

`Reveal` server-renders its children at `opacity: 0` and relies on the client
bundle to animate them in. With JavaScript unavailable, the homepage showed the
hero followed by six empty bands. Everything below the fold was invisible,
including the closing "Request membership" call to action. Dinners and coaching
were affected the same way.

Evidence: a Playwright context with `javaScriptEnabled: false` reported 15
elements stuck at `opacity: 0`.

Fix: each reveal wrapper is tagged `data-reveal`, and the root layout carries a
`<noscript>` style that forces those wrappers visible. After the fix the same
no-JS render reports 0 hidden elements and the full page renders. The animated
path is unchanged: content still starts hidden and reveals on scroll when
JavaScript runs.

Commit `d0aacb8`.

### ISSUE-002 (high): dinner and coaching leads were silently destroyed

`requestDinnerSeat` and `requestCoaching` sent the operator lead and the
requester acknowledgement inline, caught any error, logged it, and then
redirected to "Request received. A matchmaker will follow up personally with
next steps." For an anonymous requester nothing else was written anywhere, so a
rejected or unavailable mail provider destroyed the lead while the site
promised follow-up.

Evidence: two submissions produced eight provider errors in the server log and
zero rows in `DeliveryJob`. Both requesters saw the success banner.

Fix: all three intake emails (dinner lead, coaching lead, and the application
acknowledgement) are queued through the existing `DeliveryJob` outbox. They now
retry, and a permanent failure appears in the operator's "Delivery failures"
panel with a Retry button instead of vanishing. Idempotency keys use a 15 minute
bucket so a double submit collapses into one message. If the queue write itself
fails, the requester is told to email us rather than told we have the request.

Re-verified: the same two submissions now produce four queued rows, and after
the provider rejects them all four appear in the studio as recoverable failures
with masked recipients.

Commit `10064a4`.

### ISSUE-003 (medium): decorative glyphs in shipped UI

The member home rendered a large heart character as ornament in both the
opted-in and opted-out states, and the matches list used an em dash as an
empty-city placeholder. Both break the house rule against emoji and dashes in
shipped artifacts, and the heart also conflicts with the direction in
`DESIGN.md`, which asks typography and negative space to carry the page rather
than decoration.

Fix: the heart is replaced by the same small-caps eyebrow used across the site,
and the em dash by plain words. A repository-wide scan now finds no emoji, no
decorative glyph entities, and no em or en dashes in `src/`.

Commit `2b5380e`.
